# M6 ingress signature (#183)

The reusable verifier checks GitHub `X-Hub-Signature-256` as HMAC-SHA256 over exact body bytes. The intake can opt in using `-SecretFile` or `-SecretEnvVar` together with `-SignatureHeader`; verification happens before JSON parsing or ledger writes. Without a configured secret, legacy behavior remains and output states `signature_status=not-configured`. With a secret, missing or invalid signatures fail closed.

Secret files are UTF-8, trimmed, limited to 4096 bytes by default, and reject missing, empty, UNC, directories and reparse paths. Environment secrets receive the same edge whitespace trim; operators should not include leading/trailing whitespace in secrets. The standalone CLI checks file length before reading raw bodies up to 1 MiB; larger bodies return `BODY_TOO_LARGE` / exit 2 (usage/limit convention). Intake checks its 64 KiB envelope limit before reading; oversized input returns `EVENT_INPUT_TOO_LARGE` / exit 1, preserving the intake's processing-error convention. A signed UTF-8 BOM remains part of HMAC bytes and is removed only before JSON parsing. Errors do not disclose secret or expected MAC. The standalone CLI returns compact JSON with body byte count and SHA-256 digest.

This is not an operational HTTP receiver or authenticated end-to-end ingestion. Secret rotation, replay/`issued_at` validation, durable ledger operations, and a real producer/receiver remain out of scope. No production credentials, network, or webhook were used.
